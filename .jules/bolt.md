## $(date +%Y-%m-%d) - Optimization of dd block size and exiftool batching
**Learning:** Found massive bottleneck in file carving scripts that use `dd bs=1 skip=X count=Y`. The 1-byte block size forces individual read/write system calls per byte. Similarly, executing `exiftool` synchronously inside loops creates massive process startup overhead. Also learned that `exiftool -ext '*'` works but can cause redundant output files if the directory contains previously generated metadata text files, so using `-ext bin` or similar specific extensions is preferred when batching directory metadata.
**Action:** When working on file operations in Linux scripts, prefer large block sizes (e.g. `bs=4M`) with `iflag=skip_bytes,count_bytes` to drastically reduce syscalls. For command-line tools like `exiftool`, batch processing with directory inputs and wildcard extensions (`-ext bin`) via `-w` flag should be used over loop invocations.
